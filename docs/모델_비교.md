# 모델 비교 — 답변 정확성·토큰·응답 시간

같은 RAG 파이프라인에서 **LLM만 바꿔** 5개 모델을 비교했다. 서비스 기본 모델(gpt-4o-mini)을 바꿀지 판단하고, 모델별 속도·토큰 차이를 기록하려는 비교다. 서비스 설정(`.env`의 `LLM_MODEL`)은 바꾸지 않았다.

답변 원문·인용 근거·토큰·시간은 `python -m evaluation.model_compare --runs 2`를 실행하면 `docs/모델_비교_실행결과.md`(와 같은 이름의 `.json`)로 생성된다. 매뉴얼 원문 인용이 들어 있어 저장소에는 넣지 않았다.

## 1. 비교 조건

| 항목 | 내용 |
|---|---|
| 질문 | RAG 전후 비교와 같은 9문항([RAG_전후_비교.md](RAG_전후_비교.md) 2장). 질문마다 2번 |
| 파이프라인 | 서비스와 같은 LangGraph(extract 프롬프트 1 → retrieve → generate 프롬프트 3). 근거 검색·임베딩은 모든 모델이 같다 |
| 바꾼 것 | extract·generate의 LLM만. 후보 선별(프롬프트 2)은 색인 때 캐시한 결과라 모든 모델이 같은 문서 후보에서 시작한다 |
| temperature | 0. gpt-6-luna는 0을 받지 않아 기본값으로 불렀다 (조건이 완전히 같지는 않음) |

| 측정 | 2026-10-23 08:40~08:55. 팰리세이드 매뉴얼을 추가한 뒤의 색인(697청크) |

- **❌(근거와 반대)는 모든 모델에서 0건**이다. 차이는 △(일부 누락·근거 없는 단정)에서만 났다.

- gpt-6-luna 출력 608토큰 중 412토큰(68%)은 화면에 보이지 않는 추론 토큰이다. 보이는 답 길이(196)는 gpt-4o-mini(188)와 비슷하다.

## 3. 질문별 판정

**△로 본 이유**
- **#1 4.1-mini 실행 1**: "계속 주행하지 말고"라고 지시했다. 매뉴얼은 계속 주행하면 손상될 수 있으니 점검을 받으라고만 하고, 주행을 멈추라고 하지는 않는다.
- **#1 5.4-mini 실행 2**: 켜짐과 깜빡임이 다른지는 답하지 않고 "계속 달려도 되는지는 확인되지 않음"만 썼다.
- **#3 5.4-mini**: 실행 1은 '바로 켜짐 = 공기압 저하'를 빠뜨리고 차이를 "확인되지 않음"이라고 했다. 실행 2는 두 내용을 모두 쓰고도 "차이는 확인되지 않음"으로 끝내 자기모순이 됐다. 프롬프트를 개선한 뒤 gpt-4o-mini 실행 1에서 나온 것과 같은 유형이다.
- **#6 5.4-mini 실행 1, 5.4 실행 1**: 매뉴얼이 "시동을 켠 채로 정차"라고 직접 지시하는데 "시동을 끄는 게 낫지 않나?는 확인되지 않음", "아니요라고 단정할 수 있는 비교 근거는 없고"라고 답했다. 안전 지시를 흐리게 만드는 지나친 신중함이다.
- **#7 4o-mini·4.1-mini·5.4-mini, 6-luna 실행 2**: 핸즈오프 경고로만 설명하고 전동 파워 스티어링 경고등일 가능성은 밝히지 않았다.
  - 4.1-mini는 "차를 세우고 정비소에 갈 필요는 없으며"라고 단정했다. 실제로 전동 파워 스티어링 경고등이라면 위험한 안내다.
  - 6-luna 실행 2는 "핸즈오프 경고라면"이라고 조건을 달아 단정은 피했다. 하지만 다른 후보는 밝히지 않았다.
- **#8 4.1-mini 실행 2**: 근거에 없는 ICCU 기능 설명("고전압/저전압 배터리의 전원 공급을 관리하는 장치")을 덧붙였다.

**경계선**
- #3 6-luna 실행 1은 "차이를 직접 비교한 설명은 확인되지 않음"으로 시작한다. 그래도 두 경우의 뜻을 각각 근거대로 설명했다. "바로 켜진 것이 공기압 저하만 뜻하는지는 확인되지 않음"으로 범위도 정확히 한정해서 ✅로 봤다.

## 4. 눈에 띈 차이

1. **후보 신호를 각각 밝히는 규칙(#7)을 따른 모델은 gpt-5.4(2/2)와 gpt-6-luna(1/2)뿐이다.**
   - gpt-5.4는 핸즈오프 경고와 전동 파워 스티어링 경고등을 나눠, 각각 무엇을 해야 하는지 근거와 함께 썼다.
   - gpt-4o-mini는 프롬프트 개선 때와 같이 0/2다. 지금은 화면이 후보 신호를 따로 보여 줘서 보완하고 있다([RAG_전후_비교.md](RAG_전후_비교.md) 6장).
2. **5.4 계열은 "확인되지 않음"을 많이 썼다.** 18번 중 5.4-mini·5.4 각 9번, 4o-mini·6-luna 각 4번이다.
   - 근거 없는 단정을 막는 규칙을 문자 그대로 따른 결과로 보인다.
   - 그러다 #3·#6처럼 근거가 직접 답하는 질문까지 흐린 경우가 있다.
3. **gpt-6-luna는 근거의 적용 범위를 스스로 밝혔다.**
   - "팰리세이드 2024 매뉴얼 기준", "내 차가 지정되지 않아 적용 여부는 확인되지 않음"처럼 썼고, 다른 모델은 이렇게 하지 않았다.
   - 대신 답이 짧은 편이라 #4·#5에서 일부 내용(언덕길, '고장 아님')을 빼기도 했다. 핵심은 맞아 ✅로 봤다.
4. **같은 문항에서 실행 1·2 판정이 달라진 수**: 4o-mini 0, 4.1-mini 2, 5.4-mini 2, 5.4 1, 6-luna 1.
   - 이번 측정에서 gpt-4o-mini는 판정이 바뀐 문항이 없었다. #2·#5·#7은 두 번의 답이 글자까지 같았다.
   - 그동안 기록한 gpt-4o-mini의 '실행마다 흔들림'은 이번 9문항에서는 드러나지 않았다.
5. **응답 시간**: 5.4-mini가 가장 빨랐다(평균 3.4초). 5.4는 4o-mini의 약 1.5배, 6-luna는 약 2배다. 6-luna는 추론량에 따라 최대 17.5초(#7)까지 늘었다.
6. **인용 수**: 5.4가 평균 2.6건으로 가장 많았다. 문장마다 근거 번호를 여러 개 붙였다.

## 6. 결론

- **정확성은 gpt-5.4와 gpt-6-luna가 가장 높았다(✅15/16).** 차이는 대부분 #7(후보 신호 밝히기) 한 문항에서 났다.
- **서비스 기본 모델은 gpt-4o-mini로 유지한다.**
  - ✅14/16, ❌0으로 상위 모델과 1문항 차이다. 그 차이(#7)는 화면의 후보 신호 표시가 이미 보완한다.
  - 가장 저렴하고, 응답 시간도 평균 4초대다.
  - 모델을 바꾸면 화면 점검·회귀 시나리오 같은 검증을 모두 다시 해야 한다.
- **바꾼다면 gpt-5.4가 첫 후보다.**
  - temperature 0을 받아서 같은 질문에 같은 답을 재현하기 쉽다.
  - #7에서 두 후보를 모두 밝혔다.
  - 다만 #6처럼 근거가 직접 지시하는데도 "확인되지 않음"을 붙이는 경향이 있다. 그래서 프롬프트 3에 "근거가 행동을 직접 지시하면 그 지시로 답한다"를 보완해야 한다.
- **gpt-6-luna**는 정확하고 신중하다. 하지만 temperature를 고정할 수 없고, 추론 토큰 때문에 느리고 비싸다.
- **gpt-5.4-mini**는 가장 빨랐지만 정확성이 가장 낮았다. #3·#6에서 근거가 답하는 내용을 "확인되지 않음"으로 흐렸다.

## 7. 참고

- gpt-5·gpt-5.5·gpt-6-luna 같은 추론형 모델은 temperature 0을 받지 않아 기본값으로 불렀다.
- gpt-5.5는 시험 실행(질문 1개)에서 gpt-6-luna와 성격(추론형, 출력 916토큰, 13.9초)이 겹치고 비용이 커서 본 비교에서는 뺐다.
